# Project Instructions

## Идентичность проекта

- Проект: `Tourist03`
- Назначение: публичный сайт, Telegram-бот, CRM управляющих баз и Superadmin-панель
- Основной backend: `FastAPI`
- Основной frontend CRM/Superadmin: `React + TypeScript + Vite`
- База данных: `PostgreSQL`
- Бот: `aiogram`

## Что читать в начале работы

Если файлы существуют, в начале работы сначала читай:

- `AGENTS.md`
- `AGENTS_UNIVERSAL.md`
- `README.md`
- `CLAUDE.md`
- `deploy.sh`
- `deploy/.env.example`
- `Dockerfile`
- `deploy/docker-compose.yml`

Если части файлов отсутствуют, продолжай с тем, что есть.

## Обязательное стартовое понимание проекта

Перед существенными изменениями быстро зафиксируй:

1. какой контур меняется: публичный сайт, CRM, superadmin, бот, backend;
2. влияет ли задача на БД или миграции;
3. нужен ли frontend build;
4. нужен ли backend smoke-check или pytest;
5. влияет ли изменение на прод и деплой.

Если для безопасной работы не хватает прод-данных, токенов, доменов, путей, SSH-доступов или env-значений, не выдумывай их и сразу явно запрашивай у пользователя.

## Git / Push / Deploy

- После каждого завершенного изменения делай git commit с сообщением ровно из трех русских слов.
- После каждого такого коммита сразу выполняй push в основную ветку и запускай деплой через `./deploy.sh`.
- Если в корне проекта есть `.deploy.local`, используй его для локальных параметров деплоя. Пароль не храни в git и не коммить его.
- Если push или деплой блокируются правами, паролем, ключами или серверной ошибкой, сразу сообщай точную причину блокировки.

## Секреты и локальные файлы

- Никогда не коммить:
  - `.env`
  - `.deploy.local`
  - токены
  - пароли
  - ключи
  - любые секреты из серверов или внешних сервисов
- Не трогай без явной необходимости:
  - `manrope.zip`
  - `static/uploads/temp/`
- Не удаляй и не перезаписывай пользовательские локальные файлы без причины.

## Правила реализации

- Не останавливайся на анализе, если ожидается реальное изменение.
- Предпочитай существующие паттерны проекта новым абстракциям.
- Держи изменения сфокусированными.
- Не делай посторонние рефакторинги без необходимости.
- Не используй destructive git-команды без явного запроса.
- Если видишь подозрительный локальный хвост, сначала проверь, относится ли он к задаче, и только потом включай его в коммит.

## Правила проверки

Перед завершением значимого изменения запускай проверки по масштабу задачи.

Обычно применяются:

- backend:
  - `python3 -m py_compile ...` по затронутым python-файлам
  - `python3 -m pytest ...` по релевантным тестам, если они есть и уместны
- frontend:
  - `cd frontend && npm run build`
- deploy-чувствительные изменения:
  - проверка прод-страниц/ручек после выката

Если какую-то важную проверку не удалось запустить, скажи об этом явно.
